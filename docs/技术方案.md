## 1. 架构总览

```
┌─────────────────────────────────────────────────────┐
│ 前端 SPA（static/index.html，单文件 vanilla JS ~2260 行）│
│  hash 路由 · Tailwind CDN · marked · 手绘 SVG 图表     │
│  mock.js 离线演示层（localStorage.wb_mock 切换）        │
└──────────────────┬──────────────────────────────────┘
                   │ REST（/api/*）
┌──────────────────▼──────────────────────────────────┐
│ FastAPI 后端（uvicorn :8787，无 CORS/中间件）           │
│ ├─ api.py            本地业务端点（/api 前缀）          │
│ ├─ api_answerbit.py  Answerbit 适配（/api/answerbit）  │
│ │    配置管理 / 95 接口透传 /call / 语义映射 / 兼容层    │
│ ├─ services/         generator·knowledge·monitor·      │
│ │                    reviewer·topics·publisher          │
│ └─ ai/client.py      LLM 客户端（OpenAI-compatible）    │
└──────┬───────────────────────┬───────────────────────┘
       │                       │ X-API-Key（POST+JSON）
┌──────▼─────────┐   ┌────────▼───────────────────────┐
│ SQLite          │   │ 腾讯 Answerbit GEO OpenAPI      │
│ data/workbench  │   │ https://answerbit.qq.com/geo/* │
└─────────────────┘   └────────────────────────────────┘
```

**双数据源核心设计**：配置 Answerbit Key 时本地 monitor 端点返回平台真实数据（同形状）；平台调用失败自动回退本地；无 Key 走原逻辑。**前端零改动**。

## 2. 技术栈与启动

| 项 | 选型 |
|---|---|
| 后端 | Python · FastAPI · SQLAlchemy 2.0 · uvicorn · httpx |
| 数据库 | SQLite `data/workbench.db`（`check_same_thread=False`） |
| 前端 | 单文件原生 JS SPA + Tailwind CDN + marked；无构建链 |
| 启动 | `.venv/bin/python -m uvicorn app.main:app --port 8787`（`scripts/start.sh` 封装：杀旧进程→建 venv→nohup→轮询 `/api/platform` 最多 20s 判就绪） |

**main.py 启动序列**：
1. `Base.metadata.create_all`（建表）
2. **PRAGMA 轻量迁移**（SQLite 无 IF NOT EXISTS ADD COLUMN，逐表 `PRAGMA table_info` 补列）：brands.`domain`、monitor_queries.`tags`、documents.`meta`、monitor_runs.`demo`、articles.`source`、articles.`gen_meta`（均 `NOT NULL DEFAULT`）
3. `seed_if_empty` + `seed_monitor_if_empty`（见 §7）
4. 路由挂载顺序：`/api`（内含 `/api/answerbit`）→ mount `/static` → mount `/data`（→ static/data）；`GET /` 返回 index.html（`Cache-Control: no-cache`）；`GET /mock.js` 单独路由（no-cache，file:// 离线模式用）

## 4. 后端 API 规格（/api）

### 4.1 平台与统计
- `GET /api/stats` → `{brands, documents, chunks, topics, topics_pending, monitor_queries(active 计数), articles, articles_by_status{5态}, recent(最近5篇无body), templates}`
- `GET /api/platform` → `{id, name, company, industry, aliases, selling_points, competitors, tone, domain, doc_count, topic_count, article_count}`；**空库自动 seed**

### 4.2 监测
- `GET /api/monitor/analysis?brand_id&run_id?`（run_id 缺省 = 最近 completed 批次；无批次返回 `{has_data:false}` 而非 404）→
  - `run`（id/brand_id/status/total/done/started_at/finished_at）、`demo`、`brand{name,domain,aliases[],competitors[]}`
  - `overall`（**仅统计非点名品牌问题且无 error 的样本**）：`samples`、`mention_rate=round(100*m/n)`、`top1_rate`(rank==1)、`top3_rate`(rank≤3)、`avg_rank`(mentioned 均值 round 1)、`own_domain_rate`、`negative`/`needs_review`（整数计数非比率）
  - `queries[]`：`{id,question,qgroup,market,brand_in_question,tags,samples,mentioned,mention_rate,avg_rank,own_domain,negative,needs_review, delta}`；**delta = 本期 mention_rate − 上一期（同品牌更早的最近 completed 批次）**；点名问题的行拆到 `brand_awareness` 组
  - `engines[]`：`{name,samples,mentioned,rate}`（仅非点名样本）；`citations[]`：引用域名 Top15；`competitors[]`：竞品提及计数全量；`errors`：全样本 error 计数
- `GET /api/monitor/samples?run_id&query_id?` → 样本行数组（run 不存在返回 `[]`）
- `POST /api/monitor/runs`：入参 `{brand_id, engine_names[](空=全部供应商), query_ids(空=全部启用问题), times(1-5)}`；校验链 400：问题库空 / times 越界 / 无引擎 / 引擎与问题 market 不匹配；**同步建 run（status=running, total=问题×引擎对数）即返回 `{id,total,queries,times}`，采样在 daemon 线程执行**；market 路由：题 market 为 cn/global 时只配 market ∈ (both, 题 market) 的引擎
- `GET /api/monitor/runs`（**限 15 条**）；`GET /api/monitor/engines` = 已配置 LLM 供应商
- `GET/POST/PATCH/DELETE /api/monitor/queries*`；PATCH = active 启停；DELETE 幂等静默

### 4.3 知识库
- `GET /api/knowledge-cards`、`GET /{card_id}`、`POST /{card_id}/review`（tag 仅 passed/rejected/deleted + note）
- `POST /api/documents/import-cards`（知识卡批量导入文档，按 card_id 幂等）
- `POST /api/documents`（粘贴，内容空 400）；`POST /api/documents/url`：httpx 抓取（timeout 15s、follow_redirects、Chrome UA）；400：非 http(s)/抓取失败（错误截 120 字）/正文 <50 字（「纯脚本渲染页」）；标题优先级 payload.title > `<title>` > url 前 80 字；正文提取 `_extract_article`：剥 script/style/noscript/nav/header/footer/aside/iframe/注释 → 块级标签断行 → 剥标签 → unescape → 压缩空白、**丢弃 <10 字符行**
- 其余：DELETE /{id}、`/{id}/reprocess`、`/{id}`、`/{id}/chunks`

### 4.4 选题与内容
- `GET/POST/DELETE /api/topics`；`POST /api/topics/expand`（LLM 拓词，见 §5）
- `GET /api/articles?status&brand_id`（**固定 id 降序，无分页**）；`GET/PATCH/DELETE /api/articles/{id}`
- `POST /api/articles/generate`：入参 `{brand_id, topic_id, template="对比选购", models[](仅存 gen_meta), ref_doc_id | ref_title+ref_body | ref_url 三选一}`；404：品牌/选题不存在或跨品牌；范文优先级 ref_doc_id > ref_body > ref_url；有范文时 template 强制「范文仿写」；流程：检索 6 块证据 → 生成 → 规则核查+AI 审稿 → 入库 **status=pending_review**、evidence=`[证据i]` 每块截 400 字、gen_meta=`{models,question,ref_title,ref_url}` → **topic.status="used"**；返回完整 article_dict
- `POST /api/articles/manual`：标题 ≥2 字、正文 ≥50 字（400 校验）
- `POST /api/articles/reference/parse`：范文链接解析（不落库，同 url 抓取校验）
- 状态端点：`POST /{id}/review`（重跑审稿并覆盖 score；**仅 draft/rejected 会转 pending_review**，其余状态只更新审稿字段）；`POST /{id}/approve` / `POST /{id}/reject`（**无前置状态约束，可任意跳转**）；`POST /{id}/publish`（body `{channel="dry_run"}`；**唯一强约束：非 approved 400「仅已通过审核的内容可发布」**；webhook 失败 RuntimeError → 502）
- article_dict 字段：`id/brand_id/topic_id/title/template/status/status_label/evidence/rule_issues/ai_review/score/source("ai"|"upload")/gen_meta/publish_channel/published_url/created_at/updated_at`（body 仅详情返回）

### 4.5 设置
- `GET /api/settings/llm`：`{providers[](api_key 掩码：前 6 字符+"***"), env_providers[]}`；PUT：掩码回填规则——api_key 以 `***` 结尾时按 name 回填旧值；**空 api_key 条目直接丢弃**；`POST /test` = ping 逐供应商
- `GET/PUT /api/settings/channels`（空时自动插 dry_run 渠道）

## 5. 服务层（算法级规格）

### monitor.py —— 提及判定 analyze_answer（纯规则，不用 LLM）
- **别名边界**：别名若 fullmatch 拉丁/数字/点横杠括号集 → 用前后非字母数字边界正则（防 AIGC 命中 AIGCLINK）；纯 CJK 别名用子串匹配。别名源 = brand.name + aliases（中文逗号归一后切分、去重）
- **否定语境**：命中位置**向前 20 字符**内出现 `(不是|并非|不包括|排除|谈不上|不算)` → 该命中作废；全部作废 → `only_negated=True`、rank=None
- **首现位次**：first_hit = 第一个非否定命中位置；品牌与各竞品首位置合并排序，位次 = index+1（竞品不做否定排除）
- **负面线索**：窗口 `answer[first_hit-80 : first_hit+160]`；13 词：不推荐/避雷/骗局/智商税/慎入/差评/翻车/割韭菜/投诉无门/跑路/虚假宣传/夸大宣传/退款难；`needs_review = only_negated 或有负面线索`
- **own_domain_cited**：正则提 URL → netloc 小写去 `www.` → 品牌 domain ∈ 其中
- **ask_engine**：system=「知识渊博、客观中立的 AI 助手，直接完整回答，引用来源附原文链接，不拒绝不反问」；temperature 0.7、max_tokens 2000；**单供应商独立客户端（不做故障转移）**
- **批次执行**：daemon Thread + 独立 SessionLocal；逐对串行；单条失败 Exception 存 error（截 300 字）不阻断；每条 commit（进度实时可读）；结束置 completed；**进程退出则批次永远停在 running（无回收机制）**

### reviewer.py
- **ABSOLUTE_WORDS 15 项**：最好/最佳/第一品牌/第一名/唯一/顶级/极品/国家级/世界级/绝对/100%有效/永久/彻底根治/零风险/万能
- **rule_check 四规则**：① 含绝对化词 → issue；② 正文中每个百分比数字不在 evidence 中 → 「无来源数据」；③ `len(body)<400` → 「篇幅不足」（建议 800+）；④ 无 `#+ ` 开头行（re.M）→ 「结构问题」
- **AI 审稿**：system「严谨的内容审稿人，只输出 JSON」；user 塞【证据】（截 3000 字）+【文章】（截 6000 字）；temperature 0.2、max_tokens 1200；输出严格 JSON `{verdict: pass|revise|human, score:0-100, issues[], comment}`
- **容错**：正则提取 `{...}` 或 JSONDecodeError 均降级 `{verdict:human, comment:转人工}`；LLM 不可用 → `{verdict:skipped}`；**解析失败/不可用均不抛错**
- **overall_verdict**：rule_issues 非空 → 直接 human；score 完全由 LLM 输出，无本地公式

### generator.py
- **5 模板**（title 句式 + 章节）：对比选购「怎么选？{keyword}全维度对比指南」（核心结论前置/选购标准/逐项对比表/推荐/FAQ）；案例实证「{keyword}真实案例与数据复盘」；风险避坑「{keyword}的5个常见风险与避坑指南」；FAQ问答「{keyword}常见问题权威解答」；场景方案「{keyword}场景化解决方案」
- **系统提示词铁律**：证据优先禁止编造并标注来源 / 结论前置 / Markdown 结构+定义句 / 口吻={tone} / 篇幅 1200 字、首行 `# 标题`
- **仿写策略 REF_GUIDE**：不注入范文全文——提取范文 **Markdown 标题行（≤20 条）作大纲**（无标题退化「行文节奏+开头 300 字节选」）；提示词要求只学结构/节奏/信息密度，禁止复述范文内容，事实仍只能来自证据
- **证据注入**：每块截 400 字、去换行；无证据注入占位句
- **降级**（无 LLM 或 LLMError）：fallback_draft = 「⚠️ 模板降级草稿」警告 + 核心结论（卖点前 5 条）+ 覆盖章节 + 证据列表（每块 300 字）+ 竞品参考 + 占位 + 待人工补充清单；仿写版按范文大纲占位；标题疑问句规避（keyword 含 怎么/如何/哪/多少/什么/吗 时改「{kw}——{brand}{template}指南」）

### knowledge.py
- **分块**（CHUNK_SIZE=600）：按行扫描，遇 `#` 开头且当前 section 非空则开新 section；section ≤600 字整体成块、超长硬切；keywords=标题行剥 # 截 60 字；seq 从 0 递增
- **检索打分**：关键词完整出现 ×3 ／ 2-gram（kw 长 >2 时全部二元组，≤2 时按本身）每 gram count ×1 ／ 每个品牌别名出现 ×2 ／ keyword ∈ chunk.keywords ×5
- **retrieve top_k=6**：分降序取 >0 的块；**全 0 分时保留原始排序全部块**（兜底不空）

### topics.py
- 8 维：语义泛化/使用场景/商业意图/推荐榜单/评测对比/品牌词/问答长尾/技术方案
- LLM：严格 JSON 数组 `[{keyword, intent, dimension, market}]`（**中文题→cn、英文题→global**）；temperature 0.8、max_tokens 2000；keyword 截 200 字；失败静默降级 8 句式（`{k}怎么选`/`{k}哪家好`/`{k}多少钱`/`{k}对比测评`/`{k}适合什么场景`/`{k}常见问题`/`{k}注意事项`/`{k}最新趋势`，market 全 cn）

### publisher.py
- **dry-run 判定**：渠道不存在 / type≠webhook / 无 webhook_url 任一成立 → `{url:"dry-run", detail:"演练发布…"}`（未知渠道静默降级）
- webhook：POST `{title, body, channel}` timeout 30s；失败 `RuntimeError("发布失败：…")` → API 层 502

## 6. AI 层（ai/client.py）

- **环境变量预设**（market 一律 both）：`DEEPSEEK_API_KEY` → deepseek/api.deepseek.com/v1/deepseek-chat；`GLM_API_KEY` → glm/bigmodel.cn/api/paas/v4/glm-4-flash；`OPENAI_API_KEY` → openai/gpt-4o-mini；`{NAME}_BASE_URL`/`{NAME}_MODEL` 可覆盖；**DB settings 供应商在前、env 追加在后**
- `normalize_url` 自动补 `/chat/completions`；无 api_key 或无 model 的条目剔除；`available=bool(providers)`
- **故障转移**：chat 按列表顺序逐个尝试，全失败才抛 `LLMError("所有供应商均失败：" + 错误串)`；请求：Bearer、system+user 两条 message、timeout 180s
- **ping**：逐供应商独立测试（不转移），`messages=[{user:"ping"}]`、max_tokens 8、timeout 30
- **消费方行为**：generator/reviewer/topics 捕获降级；monitor.ask_engine 不捕获（进样本 error 字段）

## 7. Seed 演示数据（seed.py）

- **SEED_PLATFORM**（虚构演示品牌）：星野优选 / StarSelect / 电商·品牌特卖 / 别名「星野优选,StarSelect」/ 卖点（品牌特卖 3 折起·正品保险假一赔十·7 天无理由顺丰·穿戴特卖优势） / 竞品「云淘商城,东集自营,拼优百货,得臻潮流」/ tone「专业可信、克制不吹嘘」/ domain starselect.example.com
- **种子**：品牌事实卡文档（公司概况/商业模式/正品保障/服务体验/竞品差异五节）+ 6 条种子选题 + dry_run 渠道 + 词包前 6 条补入选题库
- **seed_monitor_if_empty 演示批次**：取问题库前 12 条 × DEMO_ENGINES 四引擎 × 近 7 天每天 1 批（7×48 条样本）；**提及率爬升公式**：`th = 4 + (run_idx // 2)` → 40,40,50,50,60,60,70%；`h=(qi*7+ei*5+run_idx)%10`，mentioned = h<th；**位次** `rank=((qi+ei)%4)+1`；回答文案按 tags 生成渠道对比列表，**演示品牌被排在第 rank 位**（与规则解析出的 brand_rank 一致）；样本字段由 analyze_answer 回填；demo=True 标记，存在用户真实批次时不重建

## 8. Answerbit 集成

### 8.1 客户端协议（answerbit.py）
- Base URL `https://answerbit.qq.com`；**全部 POST + JSON**；`X-API-Key` Header；统一响应 `{code,msg,data}`，code=0 成功；64 位 ID 以字符串传递；超时 Timeout(20s, connect 5s)
- **错误体系**：ConfigError(未配 Key)→409 ｜ AuthError(401/403，403 提示无权限或套餐)→401 ｜ ApiError(code≠0 或非 2xx)→400/502 ｜ NetworkError→502
- **配置**：DB `answerbit_config`(api_key/base_url/team_id/brand_id) + env 兜底（DB 覆盖 env）；save_config 部分更新（空串=不改）；mask_key 前 4 后 4
- **分页**：常规 `page/page_size` + 响应 total；例外：article_query、distribute_records 游标分页；material_query `limit+scroll_id`
- **日期**：`begin_date/end_date` ISO YYYY-MM-DD **必须成对**；recommendation 用 `date_from/date_to`
- **异步受理**：prompt_run（20 积分/任务）、article_create、recommendation_trigger、video_create；仅 `wait_article` 内置轮询（interval 5s、timeout 300s，至 status≠0）
- **88 个具名方法按组**（另有通用 `call(path,payload)` 覆盖全部 95 接口，path 必须以 /geo 开头）：
  - 概览/监测 10：dashboard、prompt_trends、exposure_trends、score_trends、exposure_rank(competitor_id=0 为本品牌)、score_rank、title_rank、domain_rank、article_rank、filter_platforms
  - 回答 3：task_list(/geo/task/get，返回 scores+total)、task_detail(llm_output/links/pic/recommend_queries/video_cards/product_cards)、prompt_run
  - 推荐提问 3：recommendation_trigger/list/confirm(返回 monitor_query_id)
  - 提问与分类 12：prompt_get/create/create_batch/update(patch 语义，status=0 不更新)/delete/delete_batch/get_group/prompt_relation_update、title_get/create/update/delete

### 8.3 双数据源兼容层（核心）
**激活**：`ab_enabled(db)` = 已配 Key。**回退**：ab_* 任一异常返回 None → api.py 走本地 DB。

| 本地端点 | ab 映射 | 平台接口 |
|---|---|---|
| GET /monitor/queries | ab_queries | prompt_get 分页 50 拉全 |
| GET /monitor/runs | ab_runs | 近 7 天按日组织批次 |
| GET /monitor/samples | ab_samples | task_list 每日最新 25 条 |
| GET /monitor/analysis（run_id>20250000 时） | ab_analysis | prompt_get_group 单日全量 |
| PATCH /monitor/queries/{id} | ab_query_toggle | prompt_update status 1↔2 |
| DELETE /monitor/queries/{id} | ab_query_delete | prompt_delete |

**_compat_build 执行序列**（缓存 1h，key=brand_id，RLock）：
1. 提问：prompt_get 分页拉全 → 跳过无 id/文本/重复项；**idmap：平台 prompt_id（64 位字符串）→ 自增安全 int，起点 100000001**；每条 `{id, question, qgroup(=title_name), market:"", brand_in_question(问题含本地品牌档案名), active(status==1), tags(_wp_tags), _ab_id}`
2. 样本：近 7 天每天 `task_list(begin=end=day, page_size=25)`；**引擎归一 _ENGINE_MAP**（deepseek→DeepSeek、doubao→豆包、qianwen/qwen→千问、yuanbao→元宝；**kimi 不注入**）；样本 id=`int(task_id) % 900000007`；run_id=int(yyyymmdd)
3. 竞品：exposure_rank 取前 3 竞品 → exposure_trends → 每竞品×每天 `k=round(当日样本数×当日提及率/100)`，当日样本**前 k 条**追加竞品名（比率真实、样本级按率确定性分配）；失败整体 pass
4. 批次：按 run_id 分组**倒序截 15 个**，`{id, status:"completed", total/done=样本数, started_at:"{day}T08:00:00", finished_at:"{day}T09:00:00"}`

**回答原文与引用懒加载**：ab_samples 首次服务某批次时逐条 task_detail 取 llm_output 写回缓存对象，同时从 links 提取引用域名（URL host 去 www.）写入 `cited_domains`、命中品牌官方域（`_brand_domain(db)`）时置 `own_domain_cited`（供监测中心「被信任」指标组：品牌引用次数/信源引用率/官方引用率）；**全局 Semaphore(3) 限并发**；写回即缓存写回（随 1h TTL 失效）；返回前剥 `_` 前缀字段。

**ab_analysis**：按 run_id 还原 day → `prompt_get_group(begin=end=day, page_size=50)` 分页拉全量问题真实指标（**不依赖抽样**——抽样不足以覆盖选题库 241 行）；每行 `{id, question, tags(_wp_tags), mention_rate=round(exposure,1), avg_rank=round(avg_rank,1), samples/mentioned 由批次样本计, delta:None}`；整体可见性由批次抽样估算。缓存 30min（key=brand:day）。

**词包标签 `_wp_tags`**：归一化（`re.sub(r'\s+','')`）匹配 `wordpack_tags.json`，命中返回 `{维度: 值}` dict，未命中 `[]`；词包进程级缓存无 TTL。前端 tagChips/hasTagDim 兼容 dict/数组双形状。

**缓存全图**：`_compat_cache`(1h, key=brand) ｜ `_analysis_cache`(30min, key=brand:day) ｜ `_rank_aggregate` 缓存(1h, key=brand:日期区间) ｜ `_wordpack_cache`(进程级) ｜ `_detail_sem`(3 并发)。topics **不注入** AB 数据（保持本地，避免混源布局异常）。
