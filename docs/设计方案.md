# GeoContent Workbench — GEO 内容工作台设计方案

> 基于对 Omnirank-GEO、GEORank、GeoLook 三个开源 GEO 项目的深度调研，重构出的「企业内部 GEO 内容工作台」产品设计与实现方案。核心取舍：**优先做内容模块**。

---

## 一、三个参考项目对比

### 1.1 基本盘

| 维度 | Omnirank-GEO | GEORank | GeoLook |
|---|---|---|---|
| **定位** | 自部署商用一体化 GEO SaaS：诊断→报价→写作→发布→监测→飞轮，含算力计费/分销/白标 | 开源 GEO 诊断 + AI 问答工作台（测与诊） | 单机自托管 GEO 全流程实施平台：监测→诊断→工单→资产→验收→交付 |
| **形态** | FastAPI 单体（1.28MB server.py，122 个 API 模块）+ React + PG16/Redis，单镜像蓝绿部署 | Monorepo（pnpm+turbo）：FastAPI + Next.js + PG/Redis/Qdrant/Neo4j/MinIO + Celery | Python 脚本 CLI（3 个三方依赖）+ 零依赖单页看板 + Chrome 采样扩展，数据即文件（无数据库） |
| **商业化** | 算力计费（1 元=130 算力）、三级分销、提现扣税、支付/实名 | AI 额度治理九表 + BYOK | 无（开源免费、指标口径可复现） |
| **规模感** | 5300+ 文件，写作引擎 98 文件，重工程 | 中型，工程规范好（OpenAPI 契约/迁移门禁） | 轻量克制，方法论扎实（references/ 实证） |

### 1.2 内容能力对比（本方案的关注重点）

| 能力 | Omnirank-GEO | GEORank | GeoLook |
|---|---|---|---|
| **知识库/事实** | client_profiles（客户资料：卖点/案例/人设/调性）+ kb_chunks（jieba+BM25+embedding，JSONB 存向量） | Qdrant 向量 + Neo4j 图谱（实体/关系白名单）+ 词法降级 | `facts.md` 品牌事实卡，**证据等级 A–E** |
| **选题/关键词** | selection 模块（选词、关键词报价、gap plan） | 拓词工作台：LLM 推业务画像 → 8 维生成（语义/场景/商业意图/榜单/评测/品牌/问答长尾/技术方案），AI 失败回退画像模板 | expand.py：百度下拉 + Google suggest 扩候选题，只产候选、人工勾选 |
| **内容生成** | **最强**：选题→标题多重闸→15+ 文体模板→素材+证据包→主模型写作→自动修复 | Content 四类（tutorial/template/whitepaper/announcement），RAG 问答产方案草稿 | generate.py：llms.txt、JSON-LD、FAQ 片段、大纲、`--draft` LLM 初稿 |
| **审核** | **三层闸**：规则事实核查（无来源数字/绝对化用语/虚构案例）→ AI 审稿三档（直接发/局部改/要人看）→ 医疗法律金融强制人工 | 公司提交-审核-发布 PipelineStatus | 工单系统 tasks.json + verify.py 自动验收（done/todo 回归打回） |
| **发布** | 渠道闸门（PUBLISH_CHANNEL），媒体软文投放，拒稿退费 | 公司发布状态机 draft→pending_review→published→archived | publish.py：**只接有官方 API 的平台**（GH/WordPress/公众号草稿/X/Reddit/Webhook），刻意不接 Cookie 模拟 |
| **证据优先** | evidence_pack：检索结果只是候选证据，核实后才能当事实写（默认开） | 诊断/问答带上下文引用 | 事实抽不到一律标「待确认」，每条建议可溯源到 references 实测数字 |

### 1.3 监测能力对比（本期不做，但要知道边界）

- **GeoLook 最强**：17 个 AI 引擎口径（10 个 API 自动 + 7 个人工/扩展采样），品牌提及判定是纯正则规则引擎（别名边界、否定语境、负面线索窗口、needs_review），聚合出提及率/Top3 率/位次/引用域名。
- **Omnirank**：监测任务/报告/引擎矩阵，四分类归因（被推荐/提到/未提到）。
- **GEORank**：GEO 评分引擎（schema30/content30/meta20/citation20）+ 诊断报告，**缺 query 级排名监控实体**。

### 1.4 三家共性设计模式（提炼）

无论形态差异多大，三家在内容工程上收敛出同一套模式：

1. **闭环同构**：测（可见度）→ 诊（差距归因）→ 策（选题/方案）→ 产（内容生成）→ 发（分发）→ 学（反馈飞轮）。
2. **证据优先（evidence-first）**：数字和事实必须可溯源，检索结果只是候选证据。
3. **模板化文体**：对比选购、案例数据、风险提示、FAQ 等固定文体，而非自由发挥。
4. **三层审核闸**：规则核查 → AI 审稿（三档结论）→ 人工终审。
5. **状态机驱动**：内容从 draft 到 published 是显式状态流转，每次流转有记录。
6. **降级策略**：LLM 失败回退模板/词法检索——三家都有，保证无 Key 也能跑通流程。
7. **OpenAI-compatible 多供应商**：统一接口 + 故障转移 + BYOK。
8. **数据口径可复现**：采样环境、归因纪律、指标口径写死在文档里。

### 1.5 为什么内容模块是「最先需要的」

- Omnirank 的商业化重心就是创作中心（selection→writing→publish），诊断监测是获客入口；
- GEORank 自己把内容工程划给姊妹项目 GEOFlow（作者同一人），因为「诊断出方案后要落地为内容」是刚需下游；
- GeoLook 的诊断工单最终交付物仍是内容资产（llms.txt、FAQ、文章大纲、初稿）。

**结论：企业内部 GEO 起步的第一件事，是建立「知识库→选题→生成→审核→发布」的内容流水线；监测可以后置（P2）。**

## 二、重构方案：GeoContent Workbench

### 2.1 目标与非目标

**目标（P1）**
- 企业内部使用的 GEO 内容工作台，跑通「品牌档案 → 知识库 → 选题 → 生成 → 审核 → 发布」全流程
- 零外部依赖可启动（SQLite + 内置 Web UI），未配置 LLM Key 也能降级跑通流程
- 内网可部署，配置极简

**非目标（本期不做）**
- 计费/钱包/分销/多租户 SaaS 化（Omnirank 的商业化层）
- 爬虫/Playwright、Neo4j 知识图谱（GEORank 的重基建）
- 17 引擎采样监测矩阵（GeoLook 的 P2 借鉴方向）

### 2.2 技术选型

| 层 | 选择 | 理由（借鉴来源） |
|---|---|---|
| 后端 | Python 3.9+ / FastAPI | 三个参考项目后端均为 Python，内容/AI 工具链生态最顺 |
| ORM | SQLAlchemy 2.0 + SQLite | 内网零依赖起步；模型可平迁 PostgreSQL（留 pgvector 升级位） |
| LLM | OpenAI-compatible 多供应商 + 故障转移 + 模板降级 | GEORank `ai_client.py` 模式 + GeoLook 降级策略 |
| 前端 | 原生 SPA（Tailwind CDN + vanilla JS），FastAPI 托管静态资源 | 内部工具不需要 Node 构建链；GeoLook 零依赖看板思路 |

### 2.3 架构

```
geo-workbench/
├── app/
│   ├── main.py            # FastAPI 入口 + 启动建表/种子
│   ├── database.py        # SQLAlchemy engine/session
│   ├── models.py          # Brand/Document/Chunk/Topic/Article/Setting
│   ├── api.py             # REST 路由
│   ├── seed.py            # 演示种子数据
│   ├── ai/client.py       # 多供应商 LLM 客户端（fallback 链）
│   └── services/
│       ├── knowledge.py   # 文档分块 + 关键词检索（RAG 简版，留向量升级位）
│       ├── generator.py   # 文体模板 + 证据注入 + 降级草稿
│       ├── reviewer.py    # 规则核查 + AI 审稿（三档）
│       ├── topics.py      # 拓词（8 维，LLM/模板双轨）
│       └── publisher.py   # dry-run / webhook 发布
├── static/index.html      # 工作台 Web UI
└── data/workbench.db      # SQLite（自动创建）
```

### 2.4 数据模型

| 实体 | 关键字段 | 借鉴 |
|---|---|---|
| **Brand** 平台信息（内置配置） | name, industry, aliases（别名，供提及判定）, selling_points, competitors, tone, domain；单平台专用（内置演示品牌），由 `app/seed.py` `SEED_PLATFORM` 初始化，不作为功能模块暴露 | Omnirank brands/client_profiles + GeoLook 品牌事实卡 |
| **Document** 知识库文档 | brand_id, title, content, chunk_count, source(paste/upload) | 三家知识库 |
| **Chunk** 知识分块 | document_id, brand_id, text, keywords | Omnirank kb_chunks |
| **Topic** 选题 | brand_id, keyword, intent(buyer_intent/education/probe), dimension(8 维), market(cn/global), status(pending/used) | GEORank KeywordPack/Item |
| **Article** 内容 | brand_id, topic_id, title, template, body(md), status, rule_issues, ai_review, evidence, score, published_url | Omnirank articles + GEORank Content 状态机 |
| **Setting** 配置 | llm_providers（JSON 数组）、publish_channels | GEORank Setting 运行时配置 |

**内容状态机**：`draft（生成即入）→ pending_review → approved → published`，任一态可 `rejected`（可编辑后重新送审）。

### 2.5 内容流水线（核心）

```
选题（Topic）
   │  + 品牌档案（卖点/调性/竞品）
   ▼
知识库检索（关键词打分取 Top-K 分块）──── 证据编号注入
   ▼
文体模板（对比选购/案例实证/风险避坑/FAQ/场景方案）
   ▼
LLM 生成（证据优先系统提示词；无 LLM 则模板降级草稿）
   ▼
规则核查（绝对化用语/无来源数字/篇幅）
   ▼
AI 审稿（三档：直接发 pass / 局部改 revise / 要人看 human）
   ▼
人工终审 → 发布（dry-run 或 webhook）
```

### 2.6 API 清单

```
GET    /api/stats                      仪表盘统计
GET/POST/PUT/DELETE /api/brands       品牌档案 CRUD
GET/POST/DELETE /api/documents         知识库文档（POST 自动分块）
POST   /api/documents/{id}/reprocess   重新分块
GET/POST/DELETE /api/topics            选题库
POST   /api/topics/expand              AI 拓词（LLM/模板双轨）
POST   /api/articles/generate          内容生成（含规则核查+AI审稿）
GET    /api/articles?status=           内容列表
GET/PATCH/DELETE /api/articles/{id}    详情/编辑
POST   /api/articles/{id}/review       重新审稿
POST   /api/articles/{id}/approve|reject|publish
GET/PUT /api/settings/llm              模型配置
POST   /api/settings/llm/test          连接测试
```

### 2.7 路线图

- **P1（已交付）**：品牌/知识库/选题/生成/审核/发布，全部可运行。
- **P2（已交付）：监测中心**——「先看清 AI 怎么回答，再指导内容生产」：
  - **监测问题库**：七组口径（推荐/比较/替代/价格/风险/品牌验证/场景）× 市场（cn/global）；点名品牌的问题单独归「品牌认知」，不进可见性指标（防 100% 假阳性，借鉴 GeoLook 口径纪律）。
  - **多引擎采样**：以已配置的 LLM 供应商为采样引擎（每个引擎可标记市场：全市场/仅国内/仅海外，中文题不打仅海外引擎）；后台线程执行批次，前端轮询进度。
  - **提及判定规则引擎**（纯正则，不用 LLM 判读，口径可复现）：品牌别名匹配（拉丁字符加边界防「AIGC」误命中「AIGCLINK」）、否定语境检查（「不是X」不算提及但标待复核）、负面线索窗口（首次提及 ±80/160 字内的保守负面词）、竞品排名（品牌与竞品按首次出现位置）。
  - **信源分析**：抽取回答中的引用域名 Top15、自家域名被引判定（品牌档案的官方域名）、竞品提及计数。
  - **聚合分析**：提及率/Top1/Top3/平均位次/自家域名被引率/疑似负面/待复核，按问题、按引擎两个维度 + 跨期 delta（与上一批次对比）。
  - **监测 → 生产联动**：未提及的问题一键「+选题生产」进选题库，形成「监测发现盲区 → 内容补位 → 再采样验证」闭环。
- **P3（规划）**：多渠道发布矩阵、A/B 实验、引用偏好学习反哺选题与文体选择。

## 三、部署

```bash
cd geo-workbench
pip install -r requirements.txt
uvicorn app.main:app --port 8787
# 打开 http://localhost:8787
```

LLM 配置：页面「设置」中添加任意 OpenAI-compatible 供应商（DeepSeek/GLM/豆包/OpenAI…），或设置环境变量 `DEEPSEEK_API_KEY` / `GLM_API_KEY` / `OPENAI_API_KEY` 自动注册。未配置时所有 AI 功能自动降级为模板输出，流程仍可完整走通。
